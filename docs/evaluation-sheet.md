## 4. 結果に影響しうる要因

- **実施の順番による影響（2 回目のほうが慣れている）：**
  - B は A の直後（A の終了から 14 分後）に、同じ人が同じ題材で実施した。
  - 題材と依頼文は、2 回目の時点で人がすでに知っていた。
- **2 回目に、1 回目で得た知見を使った場面（あれば具体的に）：**
  - 会話ログ（`records/conversation-b.md`）からは、A の知見を使ったと読み取れる発言は見つからなかった。
  - 本人のメモがあれば追記する。
  - 前提は A と B で逆になった。A では人が「IPv6はデュアルスタックでいったんお願いします」と答えた（A:`records/conversation-a.md` 23:03）。B では、実現性の質問で「IPv6 のみ」を選んだ（`<監査ログ>` 23:51 の `HUMAN_TURN`）。
- **そのほか（時間切れ、ツールの不具合など）：**
  - **中断:** B は 00:04〜02:50 の約 2 時間 46 分、作業を止めていた。後半にも、承認ゲートの待ちでセッションが 1 回終わっている（03:04〜03:16）。監査ログの `SESSION_ENDED` は合計 5 件。
  - **導入のつまずき:** B は開始前に、`/aidlc` が表示されない問題でセッションを作り直した（23:34、`records/conversation-b.md` のセッション 42ac1aa4）。
  - **入れ子のクローン:** 準備のときに、入れ子のクローン（`handson-aidlc/`）の評価シートに開始時刻 23:29 を書いた。実際の作業は外側のリポジトリで行っている。
  - **AI のレビューが止まった:** 1 つ目のステージで、AI のレビューを担当するエージェントの起動が 2 回とも auto mode の判定で止まった。人はレビューなしで承認した（`<監査ログ>` 1003 行目）。2 つ目以降は、起動の仕方を変えて動いた。
  - **進め方:** B は、AI-DLC が依頼文から express をもとにしたカスタムプラン（6 ステージ）を提案し、人が承認した。手順書どおり、ワークフローの種類は人が指定していない。
  - **回答の選び方:** B で、画面の選択肢から選んで答えた質問は 28 問ある。そのうち 25 問で先頭の選択肢 A を選んでいる（`<監査ログ>` の `HUMAN_TURN` の `Picked`）。最初のステージの 8 問は、選択肢の番号を入力して答えている（1、1、1、1、5、4、3、3）。
  - **effort:** A は medium と記録している。B は値を確かめていないため、A と B で同じかは不明。

## 5. まとめ（ブログに使う事実）

ここには、上の表から根拠を示せることだけを書きます。

- **人の入力と時間:** B は A の約 3.4 倍（10 回 → 34 回）の入力が必要だった。作業時間も、A の 22 分に対し、B は約 50〜65 分（数え方による）だった（1 章、2 章）。
- **承認の記録:** B では、6 回の承認が、時刻・ステージ・人の返答の原文付きで監査ログに残った。A には承認の記録がなく、終了の判断は会話の最後の 1 回だけだった（3.2）。
- **差し戻しと指摘:** A の内容は、人の問いかけ・修正依頼（3 回）をきっかけに 7 回書き直された。B では人の修正依頼は 0 回で、内容は、ステージごとの質問への回答と AI のレビューの指摘によって変わった（2 章、3.3）。
- **文書の数:** B は途中の文書を 27 残し、決定 19 件にはそれぞれ出典の質問が付いている。A の文書は本文と付録の 2 つで、途中の経過は変更履歴の表 1 つにまとまっている（2 章、3.3）。
- **仮説と判定基準:**
  - A のシナリオには、結果の予想と、遅延の差を判定する数値の基準が書かれていた。
  - B のシナリオには、結果の予想がない。遅延は、人の判断で「合否を付けず値と差を記録する」ことになった（3.1）。
  - 仮説と判定基準の書き方は、A のほうが整っていた。
- **課題の残り方:** B では、AI のレビューで見つかった 5 件（Major 3 件を含む）が未対応のまま承認された。指摘はレビューの文書に残っているが、検証シナリオ本文からはたどれない（3.4）。
