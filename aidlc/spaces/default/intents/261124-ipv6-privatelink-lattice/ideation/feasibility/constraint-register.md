# 制約一覧

インテントステートメント（`ideation/intent-capture/intent-statement.md`）と、実現性の質問への回答（`feasibility-questions.md`）から整理した制約です。

## 技術的な制約

| ID | 制約 | 出典 |
|----|------|------|
| C-T1 | 呼び出し元と呼び出される側の VPC は、どちらも IPv6 のみ（IPv4 を使わない） | Q1 |
| C-T2 | 呼び出し元は Amazon EC2 インスタンス | Q2 |
| C-T3 | 呼び出される側は AWS Fargate 上の Amazon ECS サービス | Q3 |
| C-T4 | 2 つの VPC は同じ AWS アカウントにある | Q4 |
| C-T5 | リージョンは東京（ap-northeast-1） | Q5 |
| C-T6 | 比較する経路は AWS PrivateLink と Amazon VPC Lattice の 2 つ | インテントステートメント |

## 範囲の制約

| ID | 制約 | 出典 |
|----|------|------|
| C-S1 | 成果物は検証シナリオの文書までとし、AWS 上での実行は行わない | インテントステートメント |
| C-S2 | 比較の観点は遅延とセキュリティ（アクセス制御、提供側での呼び出し元の識別）の 2 つ。可用性、スケーラビリティ、運用のしやすさなどは扱わない | インテントステートメント |
| C-S3 | 呼び出し元の識別は、ネットワーク上の情報（送信元 IP アドレス、VPC、エンドポイントなど）を対象とする | Q6 |
| C-S4 | 文書は、作成者以外の人も実施できる水準で書く | インテントステートメント |
