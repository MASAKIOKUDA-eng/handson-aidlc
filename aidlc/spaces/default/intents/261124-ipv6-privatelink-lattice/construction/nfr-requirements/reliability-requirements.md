# 信頼性（実施のしやすさと測定の確かさ）の要件

入力: `inception/requirements-analysis/requirements.md`（NFR1、NFR6、FR4.6）

| ID | 要件 | 合否の基準 |
|----|------|-----------|
| NFR1.1 | 各手順に、事前条件・操作・期待する結果を書く | 全手順に 3 点がそろっている |
| NFR1.2 | IPv6 のみの環境では、IPv4 だけで提供されているサイト（GitHub など）に届かない。そのため、使う道具と取得元を次のとおりに限る。<br>・測定: Amazon Linux 2023 に最初から入っている `curl`<br>・コンテナイメージ: 実施者が ECR に登録し、ECR のデュアルスタックエンドポイントから取得する | 手順に、IPv4 だけの取得元が出てこない |
| NFR1.3 | 1 件ごとのタイムアウトは 5 秒とする（`curl --max-time 5`）。タイムアウトやエラーは遅延の集計から外し、件数を記録する。1 セットのエラーが 1%（10 件）を超えたら、そのセットは測り直す | 手順と記録欄に、タイムアウトの値・エラー件数・測り直しの条件がある |
| NFR1.4 | 削除手順を、作成した順の逆順で書く（FR7.3） | 作成したリソースがすべて、削除手順に出てくる |
| NFR6.1 | 文書の完成の定義は、次の 3 つを満たして承認されることとする（レビュー R-06 への対応）。<br>・要件定義の FR1〜FR8 がすべて文書に反映されている<br>・本ステージの NFR が反映されている<br>・期限（1 週間以内）までに承認される | 最後のステージの承認時に、FR と NFR の対応表がある |
