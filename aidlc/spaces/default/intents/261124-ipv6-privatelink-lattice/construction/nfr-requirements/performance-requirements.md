# 性能（遅延測定）の要件

入力: `inception/requirements-analysis/requirements.md`（FR4、NFR2、NFR3）、`nfr-requirements-questions.md` Q1〜Q3。functional-design は実行していません（プランで省略）。

## 成功指標との関係（レビュー R-01 への対応）

インテントの成功指標は「記載どおりの構成・手順・測定方法・合否基準で検証を実施できる」です。遅延については、要件分析の Q4 で「合否は付けず、値と差を記録して判断材料にする」と作成者が決め、要件分析の承認（2026-11-24）で確定しました。そのため、遅延の「合否基準」は次のように読み替えます。

- 遅延の検証は、次の 2 点を満たせば「完了」とする。
  - 下の手順と条件で 3 セットの測定を終えている。
  - 記録欄がすべて埋まっている。
- 方式の優劣は判定しない。

## 要件

| ID | 要件 | 合否の基準 |
|----|------|-----------|
| NFR2.1 | 本測定の前に、ウォームアップとして 100 件を送る。ウォームアップの値は集計に含めない | 手順にウォームアップの件数と、集計から外すことが書かれている |
| NFR2.2 | 本測定は 1 セット 1,000 件とし、方式ごとに 3 セット測る（Q1） | 手順と記録欄が 3 セット分ある |
| NFR2.3 | 測定環境は次のとおりとする（Q3）。<br>・EC2: m7i.large を 1 台<br>・ECS タスク: 0.5 vCPU / 1 GB を 1 つ<br>・リクエスト: GET 1 件、応答本文は 1 KB 以下 | 環境の記録欄に、これらの値と実際に使った値を書く欄がある |
| NFR2.4 | 記録する値は次のとおりとする（レビュー R-04 への対応）。<br>・セットごと: 中央値、90 / 99 パーセンタイル、最小、最大、標準偏差、エラー件数<br>・3 セットを通した値<br>・2 方式の差 | 記録表にこれらの列がある |
| NFR3.1 | 測定はセットごとに方式を交互に行う。順番は PrivateLink → Lattice → Lattice → PrivateLink → PrivateLink → Lattice（Q2） | 手順に測定の順番が明記されている |
| NFR3.2 | 全セットを同じ日の連続した時間内に行い、開始時刻と終了時刻を記録する（Q2） | 記録欄に、各セットの開始時刻と終了時刻がある |
| NFR3.3 | 呼び出し元の EC2、PrivateLink のエンドポイント、NLB、ECS タスクは、すべて同じアベイラビリティーゾーンの 1 つのサブネットに置く。Lattice 側の経路は制御できないため、その旨を記録する（レビュー R-03 への対応） | 構成と手順で、アベイラビリティーゾーンが 1 つに固定されている |
| NFR3.4 | 測定は、両方式のターゲットがヘルスチェックで正常（healthy）になってから始める。測定中に異常になった場合、そのセットは破棄して測り直す（R-03 への対応） | 手順に、開始の条件と測り直しの条件がある |
